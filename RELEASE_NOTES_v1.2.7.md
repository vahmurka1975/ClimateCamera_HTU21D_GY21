# Release Notes — ESP32 Climate Camera v1.2.7

Дата релиза: **17.10.2026**  
Целевая платформа: **ESP32 Dev Module (Arduino-ESP32 2.0.17 / PlatformIO)**  
Дисплей: **2.4" TFT SPI 320×240 (`ILI9341_2_DRIVER`)**  
Датчик климата: **HTU21D / SHT21 (GY-21, I²C `0x40`, `SDA = GPIO 21`, `SCL = GPIO 22`)**

---

## Ключевые изменения в версии 1.2.7

### 1. Экран-заставка с часами NTP (`ClimateCamera.cpp`, `NetworkConfig.h`, `NetworkServer.cpp`)
* Добавлен автоматический переход дисплея в режим экранной заставки через **60 секунд** после последнего действия с энкодером (`CLOCK_SCREENSAVER_MS = 60000UL`).
* На заставке отображаются крупные семисегментные часы `ЧЧ:ММ` с секундным мигающим двоеточием по центру экрана и две симметричные капсулы в нижней части с актуальной температурой (`°C`) и влажностью (`%`) от датчика **HTU21D (GY-21)** (без лишних текстовых подписей, шапки и подвала).
* До завершения первой синхронизации времени по NTP индикатор часов отображает сегментные прочерки `--:--`.
* При любом повороте или нажатии энкодера заставка мгновенно закрывается, возвращая пользователя на активный экран без ложного переключения страниц или пунктов меню.
* Добавлена автоматическая синхронизация времени через SNTP (`configTzTime`) при подключении к Wi-Fi с поддержкой настройки часового пояса `CC_TZ_INFO` (по умолчанию `"MSK-3"`) и серверов `CC_NTP_SERVER_1..3` в `NetworkConfig.h`.

### 2. Оптимизация опроса датчика HTU21D (GY-21) для кабеля длиной до 150 см (`Sht30Reliable.cpp`, `ClimateCamera.cpp`)
* В программном драйвере Open-Drain I²C датчика **HTU21D (GY-21)** (`0x40`, пины `GPIO 21 / GPIO 22`) полупериод тактирования увеличен с `10` до **`20` мкс** (`HTU21D (GY-21)_HALF_PERIOD_US = 20`, частота шины ~25 кГц). Это обеспечивает двукратный запас времени установления высокого уровня на кабеле длиной 150 см при работе от внутренней подтяжки ESP32 без внешних резисторов.
* Сохранены неблокирующая двухфазная архитектура опроса (`startMeasurement()` / `readMeasurement()`), контроль контрольной суммы CRC-8 (`0x31`, `init = 0x00`), процедура аппаратного восстановления шины I²C (36 полутактов SCL + STOP + Soft Reset `0xFE`) и аварийный режим холодильника (4 мин работа / 10 мин пауза) при отказе датчика HTU21D (GY-21).
* Во время активной прошивки по воздуху (`maintenanceActive == true`) опрос датчика в `cameraLoop()` временно приостанавливается, чтобы исключить микросекундные задержки при записи блоков во Flash-память.

### 3. Повышение надёжности Web OTA и новые функции Web UI (`NetworkServer.cpp`, `WebUI.h`)
* **Автообновление CSRF-токена перед OTA:** страница `/update` перед отправкой файла `.bin` запрашивает свежий токен через `/api/status?otaToken=...`, предотвращая ошибку `Missing or invalid X-Climate-Token`, если вкладка браузера оставалась открытой долгое время.
* **Корректное освобождение режима обслуживания OTA:** если запрос `/update` отклонён на этапе авторизации, контроллер гарантированно вызывает `Update.abort()` и `releaseOta()`, возвращая нормальную работу экрана и автоматики.
* **Гарантированная доставка ответа браузеру перед перезагрузкой:** после успешной записи образа вызывается `server.client().flush()`, а задержка перед `ESP.restart()` увеличена с `700 мс` до `2000 мс`.
* **Управление учётными записями и время в веб-панели:** добавлены маршруты `/api/time`, `/api/logout` и `/api/reauth`, отображение серверного времени в шапке страницы и кнопки быстрого переключения роли (`viewer` ↔ `admin`) и выхода.

## Совместимость при обновлении с v1.2.6
* Структура настроек в энергонезависимой памяти NVS (`StoredConfig`, 52 байта, `CFG_SCHEMA = 1`, CRC-32) полностью совместима с версией `1.2.6` — все сохранённые уставки, поправки HTU21D (GY-21) и коэффициенты ПИ-регулятора сохраняются при обновлении через USB или Web OTA (`/update`).
