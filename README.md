# ESP32 Climate Camera v1.3.2 (ILI9341 2.4" 320×240 · HTU21D / GY-211)

Прошивка двухъядерного контроллера климатической камеры для сыровяления, ферментации и созревания продуктов на базе микроконтроллера **ESP32**, цветного дисплея **2.4" TFT SPI 240×320 (`ILI9341` / `ILI9341_2_DRIVER`)** и цифрового датчика температуры и влажности **HTU21D / SHT21 / Si7021 (модуль GY-211)** (интерфейс I²C, адрес `0x40`).

Актуальная папка скетча для **Arduino IDE 1.8.19** и **PlatformIO**: **`ClimateCamera_1_3_2_IDE1819`**.

  * Во всех экранных меню, веб-интерфейсе, диагностике и журнале событий обозначение датчика унифицировано как **HTU21D (GY-211)**.

* **Привязка журнала событий к реальному времени и дате:**
  * Каждая запись `CameraEvent` содержит штамп времени `epoch` (`ДД.ММ.ГГГГ ЧЧ:ММ:СС`).
  * Если события возникли в первые секунды после старта контроллера до синхронизации с NTP-сервером, то сразу после получения точного времени их штампы времени автоматически пересчитываются ретроспективно по разнице `uptime`.
  * Выгрузка журнала в файл `.txt` из веб-интерфейса сохраняет реальные дату и время каждого события.
* **Вкладка «Контроль за весом продукта» на 30 слотов в Web UI:**
  * Энергонезависимое хранение в NVS (`Preferences`, раздел `cc_prod`, ключи `p0`…`p29`) до **30 продуктов** (`Продукт №1` … `Продукт №30`) и до **64 контрольных взвешиваний** на каждый слот.
  * Кнопка **«+ Загрузить новый продукт»** автоматически выбирает первый свободный номер (`1..30`), позволяет ввести начальный вес в граммах, выбрать дату закладки из выпадающего календаря (`<input type="date">`) и задать целевой процент усушки (по умолчанию `38%`).
  * При внесении последующих контрольных взвешиваний текущая дата подставляется автоматически; в карточке продукта выводится только последнее контрольное взвешивание, текущий **процент усушки** и расчётная **примерная дата готовности** на основе фактической среднесуточной скорости потери веса.
  * Кнопка **«История взвешиваний»** открывает модальное окно со всеми замерами выбранного продукта из памяти ESP32.
  * Кнопка **«Извлечь продукт»** полностью очищает слот при выгрузке готового продукта.
* **Исправление отображения телеметрии в Web UI (v1.3.2 fix):**
  * Устранена ошибка чтения полей `d.hum` и `d.rpm` в `refresh()`, приводившая к исключению `Cannot read properties of undefined (reading 'toFixed')`; добавлена проверка `Number.isFinite()` для всех числовых полей телеметрии, уставок и карточек оборудования.

## 2. Основные возможности прошивки

### Управление температурой (Компрессор холодильника — Реле `IN4`, `GPIO 26`)
* Поддержание заданной температуры (`tempTarget`, диапазон `2.0…30.0 °C`, по умолчанию `12.0 °C`) с настраиваемым гистерезисом (`tempHyst`, `0.2…5.0 °C`, по умолчанию `1.0 °C`) и калибровочной поправкой (`tempOffset`, `-5.0…+5.0 °C`).
* **Аппаратно-программная защита компрессора:**
  * Задержка первого пуска после подачи питания: **5 минут** (`FRIDGE_START_DELAY_MS = 300000`).
  * Минимальная пауза между выключением и повторным пуском: **5 минут** (`FRIDGE_MIN_OFF_MS = 300000`).
  * Минимальное время работы после включения: **2 минуты** (`COMPRESSOR_MIN_ON_MS = 120000`).
  * Максимальное время непрерывной работы: **40 минут** (`COMPRESSOR_MAX_ON_MS = 2400000`), после чего принудительно объявляется 5-минутная пауза для защиты компрессора от перегрева.

### Управление влажностью (Увлажнитель — Реле `IN2`, `GPIO 17`)
* Поддержание заданной относительной влажности (`humTarget`, диапазон `30.0…98.0 %`, по умолчанию `80.0 %`) с гистерезисом (`humHyst`, `1.0…10.0 %`, по умолчанию `3.0 %`) и поправкой (`humOffset`, `-15.0…+15.0 %`).
* **Импульсный алгоритм без переувлажнения:** запрос на увлажнение активируется при падении влажности ниже `humTarget - humHyst` и удерживается до достижения `humTarget`. Во время активного запроса увлажнитель работает импульсами **20 секунд ВКЛ / 120 секунд пауза**, чтобы туман успевал равномерно распределиться вентилятором по объёму камеры.

### Аварийный режим при отказе датчика HTU21D (GY-211)
* Единичные помехи на линии I²C (1–2 сбоя подряд) игнорируются с сохранением последних валидных показаний.
* После **3 последовательных ошибок** чтения или устаревания данных старше **7 секунд** система фиксирует аварию датчика, **гарантированно отключает увлажнитель**, оставляет штатную вентиляцию и переводит холодильник в безопасный таймерный цикл: **4 минуты работа / 10 минуты пауза**.
* Как только датчик `HTU21D (GY-211)` снова отвечает корректным пакетом с верной CRC-8, контроллер автоматически возвращается в штатный режим.

### ПИ-регулятор оборотов вентилятора с контролем тахометра (`GPIO 16`, `GPIO 27`, Реле `IN1` `GPIO 15`)
* Циклический (`fanWorkMin` минут работа / `fanPauseMin` минут пауза) или непрерывный (`fanPauseMin = 0`) режим обдува.
* Частота ШИМ **25 кГц** (разрядность 8 бит, `0..255`), инверсная характеристика управления (`ledcWrite = 255 - output`) для согласования с NPN-транзисторным ключом.
* Стартовый форсаж **100% ШИМ в первые 2 секунды** каждого цикла для уверенного страгивания крыльчатки.
* ПИ-регулятор (`pidKp`, `pidKi` с защитой от интегрального насыщения `anti-windup`) поддерживает целевые обороты `fanTargetRPM` (`300…1500 об/мин`) по сигналам тахометра (`2 импульса на оборот`).
* **Защита от заклинивания крыльчатки:** если при заполнении ШИМ `> 100/255` обороты падают ниже `100 об/мин` дольше чем на **10 секунд**, система переходит в состояние `АВАРИЯ ТАХОМЕТРА`, отключает все реле и ждёт подтверждения оператора (`ACK` в меню или веб-панели).

### Двухъядерная архитектура FreeRTOS и защита от зависаний
* **`Core 1` (основной цикл `loop()`):** опрос датчика HTU21D, логика климата, ПИ-регулятор вентилятора, обработка энкодера, рендеринг дисплея `ILI9341` через тайловый буфер `TFT_eSprite` (обновляются только изменившиеся полосы по 16 пикселей высотой без мерцания экрана), сторожевой таймер `Task WDT` на 8 секунд.
* **`Core 0` (сетевая задача `networkTask`):** подключение к домашнему Wi-Fi (`STA`) + резервная точка доступа (`SoftAP`), HTTP-сервер с ролевой авторизацией (`viewer` — мониторинг, `admin` — управление и настройки), JSON REST API, модуль ведения 30 продуктов и безопасное обновление прошивки по воздуху (**Web OTA** на странице `/update`).

## 5. Схема подтяжки 3.3 В для датчика HTU21D (GY-211)

Датчик **HTU21D (модуль GY-211 / GY-21)** работает исключительно от логического уровня **3.3 В**. При выносе датчика внутрь климатической камеры на кабеле длиной **от 50 до 150 см** встроенной слабой подтяжки ESP32 (`~45 кОм`) недостаточно для крутых фронтов сигнала I²C, из-за чего возможны ошибки CRC или потеря `ACK`.

Для 100% надёжной работы шины I²C на длинном кабеле линии **`SDA` (`GPIO 21`)** и **`SCL` (`GPIO 22`)** подтягиваются к шине **`+3.3V`** внешними резисторами номиналом **`4.7 кОм`** (`3.3 кОм … 4.7 кОм`), а параллельно питанию датчика устанавливается керамический блокировочный конденсатор **`0.1 мкФ (100 нФ)`**.

![Схема подтяжки шины I²C датчика HTU21D (GY-211) к +3.3 В](docs/schema_htu21d_pullup_3v3.png)

### Принципиальная схема подключения и подтяжки датчика HTU21D (GY-211) (ASCII)

```text
   Контроллер ESP32                                      Модуль датчика в камере
  +-----------------+                                    +----------------------+
  |                 |                                    |   HTU21D (GY-211)    |
  |            3.3V o--------+---------+--------+------->o VIN / VCC (3.3V)     |
  |                 |        |         |        |        |                      |
  |                 |       [R1]      [R2]      |        |   Адрес I2C: 0x40    |
  |                 |      4.7 кОм   4.7 кОм   === C1    |                      |
  |                 |        |         |       100 нФ    |                      |
  |                 |        |         |        |        |                      |
  |   GPIO 21 (SDA) o--------+---------+--------|------->o SDA (Данные I2C)     |
  |                 |                  |        |        |                      |
  |   GPIO 22 (SCL) o------------------+--------|------->o SCL (Такты 100 кГц)  |
  |                 |                           |        |                      |
  |             GND o---------------------------+------->o GND (Общий провод)   |
  +-----------------+                                    +----------------------+
```

### Рекомендации по монтажу датчика:
1. **Питание только от `3.3V`:** никогда не подключайте линии `SDA`/`SCL` или резисторы подтяжки к `+5V` — выводы ESP32 и микросхема `HTU21D` не толерантны к 5 В.
2. **Учёт резисторов на плате модуля `GY-211`:** если на вашей ревизии печатной платы `GY-211` уже распаяны SMD-резисторы подтяжки `4.7 кОм` или `10 кОм` к `3.3V`, то при длине кабеля более 1 м дополнительная подтяжка `4.7 кОм` со стороны платы ESP32 снижает эквивалентное сопротивление до `~2.3–3.2 кОм`, что идеально гасит наводки от пусков компрессора холодильника.
3. **Витая пара / экранированный кабель:** при прокладке кабеля в камеру объединяйте пары `(SDA + GND)` и `(SCL + 3.3V)` и прокладывайте провод датчика отдельно от силовых сетевых проводов `220 В`.

## 6. Схема подключения вентилятора с NPN-транзистором

В прошивке реализован **инверсный закон ШИМ** (`setFanDuty(255 - output)` на `GPIO 16` с частотой **25 кГц**), специально рассчитанный под классический каскад с открытым коллектором на **NPN-транзисторе** (`BC547`, `2N2222`, `S8050` и т.п.):
* Когда программная мощность `output = 255` (100% оборотов), на пине `GPIO 16` выставляется `duty = 0` (`LOW`), транзистор **закрыт**, и внутренняя подтяжка вентилятора удерживает вход `PWM` на высоком уровне (максимальные обороты).
* Когда `output` уменьшается, транзистор открывается с частотой 25 кГц, притягивая синий провод `PWM` вентилятора к `GND` и плавно снижая обороты.
* Полное обесточивание вентилятора во время паузы цикла или остановки системы выполняется **Реле `IN1` (`GPIO 15`)**, которое разрывает линию питания `+12V`.

![Схема подключения 4-контактного вентилятора с NPN-транзистором и реле IN1](docs/schema_fan_npn_pwm.png)

### Принципиальная схема подключения 4-pin вентилятора (PWM + TACH + Реле IN1) (ASCII)

```text
   Источник +12V DC ──────────> [ COM ] Реле IN1 (управляется с GPIO 15)
                                [  NO ]
                                   │
                                   +───────────────────────────────────────┐
                                                                           │
   Контроллер ESP32                Каскад управления и тахометра           │  4-pin Вентилятор 12V
  +-----------------+                                                      ▼  +-------------------+
```

### Важные правила сборки узла вентилятора:
1. **Защита входа тахометра (`GPIO 27`):** выход `TACH` (зелёный провод, контакт 3 вентилятора) в 4-pin вентиляторах выполнен по схеме «открытый коллектор». Подтягивайте его резистором `10 кОм` **только к шине `+3.3V` ESP32** (плюс включена внутренняя подтяжка `INPUT_PULLUP`). Ни в коем случае не подтягивайте `TACH` к `+12V`!
2. **Назначение резисторов в цепи транзистора:**
   * `R_base = 1 кОм` ограничивает базовый ток с вывода `GPIO 16` на безопасном уровне `~2.6 мА`.
   * `R_pd = 10 кОм` (база–эмиттер, опционально) надёжно запирает транзистор при сбросе контроллера.
3. **Общая земля (`GND`):** минус блока питания `12V` вентилятора и вывод `GND` платы ESP32 должны быть надёжно соединены между собой.

### 7.2. Все рабочие страницы локального интерфейса и меню настроек (5 экранов + Меню)

Вращение ручки энкодера переключает 5 информационных страниц по кругу (`1/5` … `5/5`), а нажатие кнопки энкодера открывает меню настроек и редактирования уставок:

* **Страница 3/5 (`ВЕНТИЛЯТОР`):** текущие обороты по тахометру (`ОБ/МИН`), заданная цель, фаза цикла (`РАБОТА` / `ПАУЗА`) и текущий процент ШИМ.
* **Страница 4/5 (`УСТАВКИ КЛИМАТА`):** сводка заданных значений температуры, влажности, оборотов и таймеров обдува.
* **Страница 5/5 (`СОБЫТИЯ`):** последние записи бортового журнала с реальным временем `ЧЧ:ММ:СС` и датой.
* **Экран `МЕНЮ` / `РЕДАКТИРОВАНИЕ`:** изменение всех 12 параметров автоматики и сохранение конфигурации в энергонезависимую память `NVS` с контрольной суммой `CRC-32`.

#### Как работает модуль контроля веса продуктов:
1. **Загрузка нового продукта (`POST /api/products/add`):** по нажатию кнопки **«+ Загрузить новый продукт»** открывается модальное окно, где автоматически подставляется первый свободный слот (`Продукт №1` … `Продукт №30`), вводится первоначальный вес в граммах, выбирается дата закладки через выпадающий календарь (`<input type="date">`) и указывается целевой процент усушки (по умолчанию `38%`).
2. **Контрольное взвешивание (`POST /api/products/weigh`):** достаточно ввести текущий вес продукта в граммах и нажать **«Записать»** — текущая дата подставится автоматически. В карточке продукта отображается **только последнее контрольное взвешивание**, текущий процент потери веса:
   `Усушка (%) = ((W_нач - W_тек) / W_нач) * 100%`
   и расчётная **примерная дата готовности** по среднесуточному темпу потери влаги.
3. **История взвешиваний:** все промежуточные взвешивания сохраняются во флеш-памяти ESP32 (`NVS`) и доступны по кнопке **«История взвешиваний»** в виде подробной таблицы с датой, весом, дельтой в граммах и процентом усушки на каждый замер.
4. **Извлечение продукта (`POST /api/products/remove`):** кнопка **«Извлечь продукт»** очищает слот после подтверждения, освобождая номер для следующей партии.

## 9. Сборка и прошивка контроллера

### Вариант 1. Сборка в PlatformIO (рекомендуется)
В корне проекта находится готовый файл `platformio.ini`, который автоматически подхватывает настройки дисплея `TFT_eSPI_setup/User_Setup.h` и таблицу разделов `min_spiffs.csv` с поддержкой OTA:
```bash
pio run
pio run -t upload
```

### Вариант 2. Сборка в Arduino IDE 1.8.19
1. Установите ядро **ESP32 by Espressif Systems** версии **`2.0.17`** и библиотеку **TFT_eSPI** версии **`2.5.43`**.
2. Скопируйте файл `ClimateCamera_1_3_2_IDE1819/User_Setup.h` (или `TFT_eSPI_setup/User_Setup.h`) в папку установленной библиотеки `Documents/Arduino/libraries/TFT_eSPI/User_Setup.h` с заменой стандартного файла.
3. Проверьте параметры домашней Wi-Fi сети, статического IP (`192.168.0.150`), часового пояса (`CC_TZ_INFO`, по умолчанию `"MSK-3"`) и пароли ролей `admin` / `viewer` в файле `ClimateCamera_1_3_2_IDE1819/Secrets.h`.
4. Откройте скетч `ClimateCamera_1_3_2_IDE1819/ClimateCamera_1_3_2_IDE1819.ino`.
5. В меню **Инструменты (Tools)** выберите:
   * **Плата (Board):** `ESP32 Dev Module`
   * **Partition Scheme:** `Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)`
   * **Upload Speed:** `921600`
6. Нажмите **Загрузка (Upload)**.

### Вариант 3. Обновление по воздуху (Web OTA)
1. Откройте веб-интерфейс контроллера под учётной записью администратора (`admin`) и перейдите на страницу `http://<IP-адрес>/update`.
2. Выберите скомпилированный бинарный файл `firmware.bin` (`ClimateCamera_v1.3.2_OTA_firmware.bin`) и нажмите **«Загрузить и обновить»**.
3. На время записи прошивки контроллер автоматически переведёт все реле в безопасное состояние `ВЫКЛ`, освободит буфер кадра и перезагрузится в версию `1.3.2`.

## 10. Команды Serial-консоли (115200 бод)

Контроллер поддерживает интерактивное управление и диагностику через монитор последовательного порта (`115200 бод`, завершение строки `NL` или `CR+NL`):

| Команда | Описание действия |
| :--- | :--- |
| `status` | Вывод полной сводки состояния датчика `HTU21D (GY-211)`, реле, вентилятора, уставок и сети |
| `on` / `off` | Включение / выключение климатической автоматики |
| `ack` | Подтверждение и сброс аварии тахометра вентилятора (при выключенной системе) |
| `temp <значение>` | Установка целевой температуры в `°C` (например, `temp 12.5`) |
| `thyst <значение>` | Установка гистерезиса температуры в `°C` (например, `thyst 1.0`) |
| `hum <значение>` | Установка целевой влажности в `%` (например, `hum 78.0`) |
| `hhyst <значение>` | Установка гистерезиса влажности в `%` (например, `hhyst 3.0`) |
| `fwork <мин>` | Время работы вентилятора в цикле (`1..180` мин) |
| `fpause <мин>` | Время паузы вентилятора (`0..360` мин, `0` = непрерывная работа) |
| `frpm <об/мин>` | Целевые обороты вентилятора (`300..1500` об/мин) |
| `toff <°C>` / `hoff <%>` | Калибровочные поправки датчика температуры и влажности |
| `kp <число>` / `ki <число>` | Коэффициенты ПИ-регулятора вентилятора |
| `save` | Сохранение текущих настроек в энергонезависимую память `NVS` |
| `defaults` | Сброс настроек к заводским значениям по умолчанию |
| `relaytest` | Последовательный тест реле (доступен только при выключенной системе `off`) |
